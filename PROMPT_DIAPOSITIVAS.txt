DIAPOSITIVA 2 — Problema
- Título: "El Problema"
- Bullets:
  • El 65% de los jóvenes no lleva un registro organizado de sus finanzas
  • Gastos anotados en notas del celular, hojas sueltas o no se anotan
  • Se olvidan pagos pendientes y cuotas mensuales
  • No se identifica en qué se gasta más
  • No hay forma de proyectar si el dinero alcanzará para el mes
- Visual: ícono de billetera vacía o persona confundida con facturas

DIAPOSITIVA 3 — Solución y Objetivo
- Título: "Nuestra Solución: Monetty"
- Objetivo general: Desarrollar una aplicación web que permita gestionar finanzas personales de forma centralizada, con registro de ingresos, gastos y pagos pendientes, visualización de balance en tiempo real y proyecciones financieras.
- Público objetivo: Jóvenes, universitarios y cualquier persona que quiera control rápido de su dinero desde el celular
- Diferenciador: Es una PWA instalable (funciona como app nativa sin ir a tienda de apps)
- Visual: mockup de la app en celular

DIAPOSITIVA 4 — Arquitectura del Sistema
- Título: "Arquitectura de 3 Capas"
- Diagrama visual con 3 bloques conectados por flechas:
  • Frontend (React + Vite) → desplegado en Vercel
  • Backend (Express + Node.js) → desplegado en Render
  • Base de Datos (PostgreSQL) → hospedada en Render
- Flechas: Frontend ←→ HTTP/JSON ←→ Backend ←→ SQL ←→ PostgreSQL
- Nota al pie: "Comunicación via API REST con autenticación JWT"

DIAPOSITIVA 6 — Modelo de Base de Datos
- Título: "Modelo Relacional"
- Diagrama ER con 3 tablas:

  users (PK: id)
  ├── name, email (UNIQUE), password, monthly_income, created_at

  transactions (PK: id, FK: user_id → users)
  ├── type (income/expense), amount, category, description, date

  pending_payments (PK: id, FK: user_id → users)
  ├── description, total_amount, installment_amount, total_installments,
      paid_installments, frequency, due_date, category

- Relaciones: users 1──N transactions, users 1──N pending_payments
- Nota: "ON DELETE CASCADE - integridad referencial"

DIAPOSITIVA 7 — API REST
- Título: "Endpoints de la API"

  | Recurso | Endpoints | Operaciones |
  |---------|-----------|-------------|
  | Auth | 4 | Registro, Login, Sesión, Ingreso mensual |

  | Pending Payments | 5 | CRUD + Registrar cuota pagada |

- Formato de respuesta: { success, message, data }

DIAPOSITIVA 8 — Funcionalidades Principales
- Título: "¿Qué puede hacer el usuario?"
- Lista con íconos:
  ✅ Registrarse e iniciar sesión de forma segura
  ✅ Configurar ingreso mensual fijo
  ✅ Registrar ingresos y gastos con categoría y fecha
  ✅ Editar y eliminar movimientos
  ✅ Filtrar por categoría, tipo y rango de fechas
  ✅ Registrar pagos pendientes (únicos, mensuales o por cuotas)

  ✅ Gráfico de gastos por categoría

  ✅ Instalar como app en el celular (PWA)

DIAPOSITIVA 9 — Seguridad y Validaciones
- Título: "Seguridad del Sistema"
- Bullets:
  • Contraseñas encriptadas con bcrypt (10 salt rounds)
  • Tokens JWT con expiración de 7 días
  • Validación en 3 niveles: Frontend (HTML5 + JS) → Backend (express-validator) → BD (constraints)
  • Cada usuario solo ve sus propios datos (filtro por user_id del token)
  • CORS configurado para permitir solo el dominio del frontend
  • Protección contra inyección SQL (Sequelize parametriza queries)
